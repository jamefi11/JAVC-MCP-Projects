TROUBLESHOOTING
================

Q: "ModuleNotFoundError: fastmcp"
A: pip install fastmcp

Q: "database is locked"
A: rm lab.db && python threat_lab_client.py

Q: Server doesn't respond
A: Check Python version: python --version (need 3.10+)

Q: No output at all
A: Ensure both .py files in same directory
   cd ~/mcp-threat-lab
   ls -la threat_lab*.py

Q: Permission denied on .env file
A: chmod 644 test_files/secrets/.env

WHAT EACH FILE DOES
====================

threat_lab_server.py
  - FastMCP server with 5 tools
  - 3 vulnerable: poisoned_query, injection_vulnerable_query, overscoped_file_access
  - 2 safe: list_users, get_user
  - Runs on stdio transport
  - Communicates with test client via JSON-RPC

threat_lab_client.py
  - Main test harness you run
  - Launches server as subprocess
  - Calls each tool with attack payloads
  - Observes results and database state changes
  - Reports findings for each threat
  - ~500 lines, extensively commented

setup_threat_lab.sh
  - One-time initialization script
  - Creates ~/mcp-threat-lab directory
  - Sets up Python virtual environment
  - Installs fastmcp via pip
  - Creates test file structure
  - Initializes SQLite database with 3 test users
  - Creates injection payloads and secrets

MCP_Threat_Lab_Guide.md
  - Comprehensive step-by-step guide
  - 400+ lines of detailed documentation
  - Backend options (SQLite vs PostgreSQL)
  - Code walkthrough for each threat
  - Hardened (safe) implementations
  - Advanced topics and next steps

THREAT_LAB_README.md
  - Quick reference (this file)
  - Setup instructions
  - Expected output examples
  - File directory structure
  - Observations to make
  - Troubleshooting

WHAT YOU'LL OBSERVE
===================

Threat 1: Tool Poisoning
  ✗ User record deleted from database
    (count drops from 3 to 2)
  Why: Tool's actual implementation violates its schema declaration

Threat 2: Prompt Injection
  ✗ Tool returned unescaped file content with injected directives
    (contains "SYSTEM PROMPT OVERRIDE", "IGNORE_SAFETY_CHECKS")
  Why: Tool result inserted directly into LLM prompt without sanitization

Threat 3: Over-Broad Scope
  ✗ Tool accepted directory traversal paths (../) and absolute paths
    (.secrets/.env, ./server.py both readable)
  Why: Schema declares narrow scope but implementation has no validation

NEXT STEPS
==========

1. UNDERSTAND: Read MCP_Threat_Lab_Guide.md (detailed explanations)

2. EXPERIMENT: Modify threat_lab_server.py
   - Change the magic bypass string: '--UNSAFE_BYPASS' -> '--SECRET123'
   - Rerun: python threat_lab_client.py
   - Observe: Attack still works if you use new bypass string

3. HARDEN: Implement safe versions in new file threat_lab_server_hardened.py
   - Remove magic strings
   - Add output boundary markers
   - Enforce path validation with allowlist

4. COMPARE: Run both servers side-by-side
   - Vulnerable: python threat_lab_client.py
   - Hardened: python threat_lab_client_hardened.py
   - Observe: Which attacks succeed? Which are blocked?

5. INTEGRATE: Add LLM client
   - Use Claude API to invoke tools
   - Watch how LLM responds to injected prompts
   - Test if LLM detects malicious payloads

6. SCALE: Test with PostgreSQL backend
